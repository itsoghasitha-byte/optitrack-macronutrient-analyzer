# OptiTrack Macronutrient Analyzer

A mobile-responsive full-stack nutrition dashboard built with Python, FastAPI, Pydantic, Plotly and optional Supabase Postgres persistence.

## Features
- Futuristic animated dashboard and responsive glass UI
- Editable calorie, protein, carbohydrate and fat goals
- Searchable starter food library with 10 foods and one-tap form fill
- Custom meal logging, listing, deleting and refresh
- Macro calorie split and daily calorie trend charts
- Validated REST API, interactive Swagger docs, pytest and GitHub Actions CI
- Optional Supabase persistence through server-side environment variables

## API routes
- `/` frontend
- `/api/health` backend status
- `/api/foods?q=chicken` food search
- `/api/analyze` macro calculations and goal progress
- `/api/entries` meal CRUD
- `/api/insights` summary metrics
- `/docs` interactive Swagger documentation

## Local run
Python 3.12 recommended.
```bash
pip install -r requirements.txt
uvicorn index:app --reload
pytest -q
```

## Optional Supabase persistence
Without credentials, entries use in-memory demo storage and may reset on serverless restarts. For persistence, create a `nutrition_entries` table with columns: `id bigint generated by default as identity primary key`, `name text`, `calories double precision`, `protein double precision`, `carbs double precision`, `fat double precision`, `entry_date date`, and `created_at timestamptz default now()`. Set Vercel environment variables `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, optionally `SUPABASE_TABLE`. Keep service-role credentials server-side only. A public app with shared entries is not private; add authentication and per-user row-level security before storing personal data.

## Notes
Food figures are approximate examples, not medical advice or personalized dietetic recommendations. Demo storage is not permanent. This is a portfolio showcase, not a clinical nutrition product.


## Vector tracking and exploration engine

The repository now includes `exploration_engine.py`, a dependency-free Python reference module implementing vector tracking, angle-threshold turn/change detection, and 2D occupancy-grid raycasting, plus `tests/test_exploration_engine.py` covering normal cases and invalid inputs.

- **Use case:** macro-goal exploration; translate project measurements into 2D coordinates before interpreting the generic algorithm's results.
- **Run tests:** `python -m pytest -q`.
- **Scope:** this raycast is a generic grid primitive, not geographic collision avoidance, official aviation routing, medical advice, or real-world navigation.

The existing GitHub repository and live-demo URLs remain unchanged. Python is the implemented reference engine. C++23 with Conan/vcpkg, Rust, PHP/Symfony/Mago, and Django are not represented as integrated runtimes in this change; they should be added only as tested adapters where the project's architecture benefits from them, rather than forcing every framework into every app.
